# СтройуниВЕРсал

Интернет-магазин строительных и отделочных товаров.

## Текущий статус

Frontend-прототип опубликован на GitHub Pages. Реализованы главная страница, каталог с поиском/фильтрами, карточки товаров, корзина с изменением количества и предварительная страница оформления заказа.

**Оформление заказа пока демонстрационное:** данные не отправляются и не сохраняются, оплата не принимается. Товары, цены, наличие, изображения и характеристики необходимо подтвердить у продавца.

## Стек frontend

- React + TypeScript
- Vite
- React Router
- Lucide icons

## Backend — начальная основа

В каталоге `server/` подготовлен отдельный Node.js API:

- Express + TypeScript;
- Prisma ORM и схема PostgreSQL;
- базовые модели пользователей, адресов, категорий, товаров, корзин, заказов и платежей;
- `GET /api/health` проверяет доступность API и PostgreSQL;
- Helmet и ограничение CORS по списку разрешённых frontend-origin.

### Требования

- Node.js 20 или новее;
- PostgreSQL;
- отдельный хостинг backend и БД.

### Запуск API локально

```bash
cd server
npm install
cp .env.example .env
```

Заполните `.env` реальным `DATABASE_URL`, затем:

```bash
npm run prisma:generate
npm run prisma:validate
npm run build
npm run dev
```

После настройки PostgreSQL примените миграцию:

```bash
npm run prisma:migrate
```

Проверка: `http://localhost:4000/api/health`.

## Безопасность и публикация

- Не добавлять реальные `.env`, пароли, ключи и токены в GitHub.
- Перед подключением реальных покупателей нужно выбрать хостинг API и БД, настроить резервное копирование, HTTPS, логи и мониторинг.
- Для российского ИП отдельно проверить требования 152-ФЗ, локализацию персональных данных и 54-ФЗ с учётом фактической схемы продаж.
- ЮKassa будет подключаться только на сервере. Статус оплаты должен подтверждаться проверенным уведомлением (webhook) провайдера, а не возвратом пользователя на frontend.
- До запуска продаж нужно заполнить реквизиты ИП, контакты, правила доставки/возврата и обязательную информацию для покупателей.
